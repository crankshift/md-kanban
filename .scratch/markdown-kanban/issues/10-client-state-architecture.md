# 10: Move client state into the URL, query cache, and editor

Status: ready-for-agent
Blocked by: 08

## Outcome

The board keeps its current look, but its state follows ADR 0005: views are restorable from the URL, file data and writes go through one query cache with optimistic updates, and drafts live only in their open editor. The later Chakra rebuild then only replaces the view layer.

## Scope

- Add React Router, nuqs, and TanStack Query. Do not add app-owned React Context or a global store; library providers are the only context.
- Keep the workflow, search text, location, feature or effort, open issue, open document, and create form in URL search params. Browser Back closes the open issue or document, or returns from a followed link. Serve the client for non-API paths so deep links resolve.
- Read the board, supporting documents, opened documents, creation targets, and session context through queries. Live file-change events invalidate them; refetches wait while a write is in flight so a late response never shows an unsaved state. This replaces the hand-written request counters and refresh queue in `Board.tsx`.
- Make every write a mutation with an optimistic update and rollback: status moves, editor saves, comments, and issue creation. A created issue appears without a number, marked as being created, until the server confirms its number. Keep stale-write rejection for every write.
- Replace retained multi-issue drafts with editor-only drafts: unsaved changes exist only while that issue's editor is open, and closing it asks for confirmation. Remove the draft list. An external change to the open issue keeps the draft and shows which fields changed on disk and in the draft, with "Discard mine" and "Reapply mine on latest"; fields changed on both sides need an extra confirmation. A save that fails after the editor closed offers to reopen the editor with the submitted values.
- Move client-only packages to `devDependencies`; runtime `dependencies` are only what the server needs (`zod`, `open`).
- Add `CHANGELOG.md` in Keep a Changelog 1.1 format with an `Unreleased` section summarizing tickets 01–08 and this ticket. Document in `CONTRIBUTING.md` and `docs/agents/issue-tracker.md` that every ticket updates `Unreleased` in its own commit.
- Leave the visual design and the prototype under `src/client/prototype/` untouched.

## Acceptance criteria

- Reloading or sharing a URL restores the workflow, filters, and the open issue or document; browser Back closes or returns as described.
- Status moves, saves, comments, and creation appear immediately and roll back with a visible error when the write fails or is stale; a failed status move never stays shown as saved.
- A created issue shows no number until the write is confirmed.
- External changes refresh untouched issues without disturbing an open editor; a conflicting draft offers both recovery choices and never overwrites silently.
- No app-owned `createContext` or global store exists in `src/client` outside the prototype.
- The packed package installs only `zod` and `open` as runtime dependencies and still launches.
- `CHANGELOG.md` exists and the contribution docs describe the update rule.
- Existing behavior tests are updated for the new draft model and pass, along with type checking and the production build.

## Comments

### Implementation result — 2026-10-06

- Implemented ADR 0005 with React Router and nuqs for URL view state, TanStack Query for file reads and every write, and a draft snapshot/form owned only by the open editor. Workflow, search, location, feature/effort, issue, document/fragment, and creation-form visibility survive URL sharing/reload. All URL writes use router navigation so Back and editor-close confirmation share a boundary; followed links keep history. Non-API navigation routes serve the packaged client, while missing assets/API routes stay 404. The existing visual design, CSS, and prototype files are unchanged; no app-owned Context or global store was added.
- Board, session context, supporting-document list, opened documents, and creation targets use `disk` query keys. SSE connection/change and focus invalidate those queries. Mutations cancel in-flight reads before changing the cache; queries pause during writes and their query functions also wait on the mutation cache, including explicit refetches. Settlement invalidates disk data without awaiting a refetch that must wait for the mutation itself. Query cancellation/structural sharing replace Board's request counters, merge logic, and refresh queue. The production App keeps cached Board/editor instances mounted on background board/context read errors, with visible error messages.
- Status moves, editor saves, comments, and creation update the query cache immediately and roll back on rejection or unconfirmed persistence, with a visible error and disk refresh. Creation shows `Creating…` with no number until confirmation; confirmed creation switches workflow, clears filters, and opens the returned issue. Every existing-issue request retains its loaded `expectedRevision`, and creation retains its container snapshot revision. The existing session/origin checks, targeted Markdown transforms, shared writer, and exclusive creation boundary remain authoritative; no new direct file write or deferred product feature was added.
- Removed the retained multi-issue draft list. Closing an editor/creation form, changing issue, following a document link, and browser Back ask before discarding unsaved work; cancellation leaves the form mounted. Reload/focus/file events preserve an open draft, including copyable recovery while its file is removed or malformed. Conflicts list fields changed on disk and in the draft, with `Discard mine` and `Reapply mine on latest`; overlapping fields require extra confirmation. Field saves retain unsent comments, and comment saves retain unsaved fields. Failed mutation variables hold submitted values and offer reopening after editor closure, including after a later status move; successful editor recovery or explicit discard clears failed snapshots. Unsaved values are never stored in the URL or browser storage.
- Extended watcher fingerprints to regular Markdown stat versions, including ADRs and ordinary linked documents, so live events refresh supporting-document queries too. Symlinks and ignored directories remain excluded. Descendant read/stat failures are represented individually so they do not suppress healthy issue notifications; root failures still use the existing polling/recovery path.
- Added current React Router 8.4.0, nuqs 2.10.1 (v8 adapter), and TanStack Query 5.104.1; moved React, React DOM, React Hook Form, react-markdown, and remark-gfm to devDependencies. Packed runtime dependencies are only `open` and `zod`. Router 8 requires Node 22.22+ for checkout development; the prebuilt CLI retains Node 22.12+ support. Consulted current official library documentation through the installed `find-docs`/Context7 CLI, including v8 adapter compatibility, mutation rollback/cancellation, navigation blockers, and offline pnpm installation. Added Keep a Changelog 1.1 `CHANGELOG.md` with Unreleased entries for tickets 01–08 and 10; README, CONTRIBUTING, and tracker guidance describe the new behavior and per-ticket changelog rule.

Targeted board/form/document/live-refresh/state tests and type checking ran during implementation.
